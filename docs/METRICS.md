# 业务与数据口径

本项目是合成数据的教学/作品集项目。数据期间不等于开发时间；README、Git 提交不会伪造 2025.12—2026.06 的开发履历。没有真实医院系统接入、业务收益或实际部署证据。

## 数据粒度

| 表 | 唯一键 | 粒度与规则 |
| --- | --- | --- |
| registrations | registration_id | 一次挂号；同一人多次挂号计多次，不是患者人数 |
| visits | visit_id，registration_id 唯一 | 一次挂号最多一个就诊状态，completed/pending；取消挂号不能关联就诊 |
| charges | charge_id | 一条支付或退款流水；金额为正，方向由 kind 确定 |
| daily_metrics | 日期＋科室＋时段 | 支付/退款先按挂号汇总，再与挂号表关联，避免多对多放大 |

挂号日期、科室、时段是统一归属维度。演示生成器在同一挂号队列内生成收费与退款。自定义数据的晚到退款会重算原挂号日，不代表到账日现金流水；本模型没有跨期会计账务与收费项目维度。若接 HIS，需添加事件时间、账务日期与结算状态，并另建现金口径指标。

## 指标

| 指标 | 算法 | 边界 |
| --- | --- | --- |
| 门诊量 | status=valid 的挂号数量 | cancelled 不计入，但保留审计记录 |
| 就诊量 | status=completed 的就诊数量 | pending 不计入；不按收费行数计算 |
| 支付金额 | payment 正数求和 | 内部使用整数分，避免二进制浮点累计误差 |
| 退款金额 | refund 正数求和 | 净收费＝支付－退款，可能为负，不能简单删掉 |
| 客单价 | 净收费 / 完成就诊量 | 分母为0时 NULL；是每就诊人次收费，不是每独立患者收费 |
| 完成率 | 完成就诊量 / 有效挂号量 | 分母为0时 NULL |
| 月度同比/环比 | (本月－去年同月/上月) / abs(基期) | 仅完整自然月；缺失月份或基期0时 NULL |
| 首页比较 | 前等长期间、去年对应起止日期 | 与自然月环比不同；覆盖不足、闰年天数不等则不可比较 |

日历从 manifest 的 start/end 补齐日期×科室×时段零值。无 manifest 的自定义 CSV 只能以有效挂号的最早/最晚日推断覆盖；生产数据应提供采集完整性标识，不能将停采当作零业务。

## 清洗策略与审计

列名、顺序不符直接失败，不覆盖数据库。每行必填值、字段长度、日期、枚举和金额必须通过校验。完全重复保留首条，后续行记为 exact_duplicate；同一主键不同内容全组隔离，避免随意猜测哪个版本有效。多个不同 visit_id 指向同一挂号时全部隔离；挂号被隔离后，其下游关联也隔离。

`quality.json` 对每张表记录 input = accepted + quarantined；`quarantine.json` 保存表、CSV 原始行号、原因、原始内容。输入 SHA256 写入 run_report。数据库加载使用事务；重新执行是受控的演示库全量替换，仅应用于独立 `hospital_demo` 库。

## 异常规则

对“日期×科室”的挂号量和净收费，以此前最多8个同星期日的均值作为基线，至少4个历史样本。

`abs(实际－基线) > max(3 × 历史总体标准差, abs(基线) × 30%, 最小变化)`。

最小变化：挂号5人次；收费5000分。历史只使用目标日前的数据，不用未来信息。零业务日也进入历史；不会自动区分停诊与漏采。阈值和样本量都输出以便复核。该规则可能误报，未做临床或真实业务效果评估，不能宣称准确率。模拟注入两类异常不代表总共只能检出两条异常。

## AI 边界

指标由 SQL/Python 计算，大模型只接收聚合指标和最多20条异常，不能直接访问数据库或执行 SQL。Prompt 强制区分事实/假设、明确金额单位、禁止编造因果；这不保证模型绝不出错。必须以原指标核验。未调用 API 的输出明确标注规则摘要；真实 API 调用需要用户自己的兼容服务配置。
